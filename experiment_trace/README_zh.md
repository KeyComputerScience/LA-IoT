# 实验实施与追溯说明

本目录是实验设计和记录模板，尚未执行实验。模板中的规模、敏感比例和重复次数是建议配置，不能作为已完成实验写入论文。没有填写的值必须通过配置或测量补齐，不能填入原文旧结果。

## 平台与角色

- Cortex-M3、32,768 字节 RAM 是目标传感节点配置；必须补充具体 MCU、时钟、Flash、无线芯片和完整固件。
- Raspberry Pi 4 仿真传感节点行为并执行现有密码流程。Pi 时间、进程内存和板级能耗只能标为 Pi 测量。
- Cooja 模拟 CoAP/RPL/6LoWPAN/IEEE 802.15.4 网络。保存 mote 类型和版本，不能把普通 Cooja mote 当作 Cortex-M3 的周期仿真。
- regional aggregator、controller 和 recipient 是分别记录的角色。若在同一台 Pi 上运行，保存角色与进程的对应关系；不能称为多个物理设备。
- 现有 Python 包未包含已验证的 Contiki/CoAP 网络适配器。把序列化报文接入网络仿真、记录 CoAP 分块与 6LoWPAN 分片，以及注入处理延迟，需要单独实现并验证。

## 开始实验前必须补齐

1. 固定源码提交、库的实际版本、BFV 完整参数、编译选项、CPU 策略、拓扑和源数据文件。
2. 确定报告周期、预热时间、测量时长、轮次截止时间、路由配置、无线模型、队列大小和重传规则。
3. 确定 CoAP block 大小和接收缓存上限，验证最大 BFV 报文可以完成传输。源 MAC 覆盖完整逻辑报文，分块重组成功后才允许加入聚合。目标设备的缓存也必须纳入 RAM 检查。
4. 导出实际 BFV coefficient-modulus 参数和上下文标识。当前参考配置为四个整数、绝对值不超过 100、精度 1、先验均值 0 和精度 1；每次更改必须重新检查整数范围。
5. 给每个节点配置独立来源凭据，并使用独立的结果凭据。拓扑、数据和攻击选择可用记录的随机种子；不得用这个种子生成密码随机值，也不把秘密密钥写入日志。
6. 独立明文参考程序从输入和参与者列表计算分子、分母、均值和方差，不调用被测聚合函数充当参考。
7. 如需 Cortex-M3 耗时、内存或能耗结果，补充该目标实现的测量。Pi 的耗时不能按频率比例换算；Pi 的 RSS 也不能与 32 KB 直接比较。

## 每次运行

复制 run_manifest_template.json，填写唯一 run_id，并保存配置的 SHA-256。三种运行类型分别使用 pi_profile、network_simulation、target_firmware_validation。

为每次运行保存：manifest、环境记录、输入、拓扑、攻击时间表、原始事件、网络跟踪、结果记录、独立明文参考结果、分析脚本及其版本。所有记录用 run_id 关联。

events_template.csv 是事件字段模板。report_hash 对应完整源报文；CoAP transfer、block、datagram、fragment、frame 和 hop 字段用于把一个逻辑贡献追溯到实际链路发送。每条重复发送有独立事件，不能只记录最后成功的一次。

verification_status 记录观察结果，例如 accepted、rejected、idempotent_retry、incomplete；rejection_code 仅用于本地实验诊断，对外接口仍使用统一拒绝响应。source admission 与 contribution accepted 要使用不同 stage，因为最终密码验证可能发生在轮次结束时。

模拟时间和宿主单调时钟是不同 clock_domain，不能直接相减。跨主机时间差需要同步方法与误差记录。由 Pi profile 注入网络的延迟属于 Pi-assisted model，不属于 Cortex-M3 实测。

## 验收与结果统计

- 恢复正确性：合法敏感报告恢复的字节与原始字节完全相同。
- 计算正确性：完整轮次的加密统计与独立参考程序整数、精确分数完全相同。相同贡献重排不能改变答案。
- 完整性：新增篡改内容不得被当作有效贡献；重复报告不重复计入；缺失必要报告的轮次保持 incomplete。
- 中间结果：改变 relay partial 而保留合法原始报告时，controller 的接受结果仍以原始报告重算为准。
- 资源：目标完整路径的静态区、最大同时 stack/heap、通信缓存及保留空间合计不超过 32,768 字节；Flash 同时满足具体 MCU 约束。BFV 不能仅凭 Pi 运行成功判为通过。
- 通信：记录原始副本、临时聚合、每跳分片、ACK、重传、RPL 控制流量和最终结果，保持层级定义一致。源 JSON/base64 编码开销也计入。
- 能量：Pi 板级积分按实际测量窗口统计；共享主机上多个角色的重叠板级窗口不能相加。目标网络模型需要带出处的状态功率，且说明 CPU 与 radio 是否重叠。
- 可用性：已计划、完成、缺失、超时轮次数量都保留。延迟只描述已完成轮次时必须同时报告完成率；不能丢弃失败运行来改善均值。
- 攻击：5,000 个来源中 250 个被攻陷来源等于 5%。恶意网关比例以网关数为分母，修改强度以 eligible reports 为分母；分别记录实际整数数量。
- 持有合法来源密钥的设备可认证虚假测量。它产生的估计误差不计为未检测出的 MAC 伪造。丢包与 DoS 成功也不能计为密码破解。

run_summary_template.csv 一行对应一个 run 的一个指标。measurement_kind 使用 measured_pi、modeled_network 或 measured_target，缺测值留空并说明原因，不能填 0。

统计以独立 run 为单位，按相同种子与工作负载配对比较。保留样本量、均值或中位数、95% 置信区间及超时数量。观察到零次非法接受时报告尝试次数和统计上界，不能声称密码安全率为 100%。

figure_provenance_template.csv 记录图中每个系列使用的汇总表、run 集合、脚本哈希和命令。图表只从日志汇总生成，不手填优势、检测率或量子抗性百分比。
